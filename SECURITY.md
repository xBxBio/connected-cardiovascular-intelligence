# xBxBio Security Policy

## Security Matters

xBxBio takes the security, privacy, integrity, and responsible disclosure of information seriously.

This public repository supports selected non-proprietary materials associated with **xBxBio Connected Cardiovascular Intelligence™**.

Because xBxBio operates in a healthcare-technology context, security concerns may have implications beyond traditional software security, including potential impacts involving privacy, clinical information, healthcare data, system integrity, and patient safety.

xBxBio encourages responsible reporting of legitimate security concerns.

---

## Reporting a Security Concern

**Do not publicly disclose suspected security vulnerabilities through GitHub Issues, Discussions, pull requests, comments, or other public channels.**

Public disclosure of an unaddressed vulnerability may unnecessarily increase risk.

If you believe you have identified a legitimate security concern involving xBxBio, contact:

**[ken@xbxbio.com](mailto:ken@xbxbio.com)**

Use a subject line similar to:

**Security Report — xBxBio**

Please provide only the information reasonably necessary to understand and evaluate the concern.

Do not include patient information, credentials, secrets, or other sensitive information unless xBxBio has specifically provided an appropriate secure method for transmitting that information.

---

## What to Include

When reporting a potential security issue, include information such as:

* A clear description of the concern
* The affected public repository, resource, or component, if known
* The circumstances under which the issue was observed
* Reproduction information when appropriate and safe to provide
* Potential impact
* Relevant technical observations
* Your preferred contact information if you would like a response

Please avoid including unnecessary sensitive, confidential, proprietary, or personally identifiable information.

---

## Patient Information and PHI

**Do not include real patient information, patient-identifiable information, or protected health information (PHI) in a security report submitted through ordinary email, GitHub, or other public or unsecured channels.**

Do not send:

* Patient names
* Medical-record numbers
* Patient account information
* Patient email addresses
* Patient telephone numbers
* Full dates of birth
* Identifiable medical records
* Identifiable medical images
* Patient credentials
* Device identifiers linked to identifiable patients
* Other information capable of identifying an individual patient

If a suspected security issue appears to involve patient information, report the **existence and general nature of the concern without transmitting the patient information itself**.

xBxBio can determine whether an appropriate secure communication method is necessary for further evaluation.

When uncertain:

**Do not transmit the patient information.**

---

## Do Not Publish Sensitive Security Information

Do not publicly post:

* Passwords
* API keys
* Access tokens
* Private keys
* Authentication credentials
* Security secrets
* Sensitive configuration information
* Exploit code targeting xBxBio
* Detailed instructions intended to facilitate unauthorized access
* Non-public infrastructure information
* Security architecture
* Internal network information
* Confidential system configurations
* Information that could facilitate unauthorized access
* Patient-system access information
* Confidential vulnerability information

If sensitive information has already been accidentally posted publicly, avoid reproducing, quoting, copying, or redistributing it.

Notify xBxBio at **[ken@xbxbio.com](mailto:ken@xbxbio.com)** as soon as reasonably possible.

---

## Responsible Security Research

xBxBio supports good-faith security research conducted responsibly and lawfully.

Security researchers should not:

* Access information beyond what is reasonably necessary to identify or demonstrate a suspected issue
* Access, acquire, modify, delete, copy, or disclose patient information
* Access another user's private information
* Access confidential xBxBio information
* Degrade or disrupt services
* Perform denial-of-service testing
* Introduce malicious software
* Attempt social engineering
* Conduct phishing
* Use compromised credentials
* Establish persistence
* Exfiltrate information
* Modify production information
* Circumvent security controls beyond what is lawfully authorized
* Publicly disclose an unresolved vulnerability in a manner that unnecessarily increases risk

If testing could reasonably affect systems, information, users, healthcare operations, privacy, security, or patient safety, appropriate authorization should be obtained before proceeding.

This repository contains **selected public and non-proprietary information**.

It does **not** represent the complete xBxBio platform, production environment, infrastructure, security architecture, internal architecture, proprietary implementation, or security-control environment.

The absence of a technology, control, component, architecture, process, or security mechanism from this public repository should **not** be interpreted as evidence that it is absent from xBxBio systems.

Public materials should not be used to infer confidential xBxBio architecture, infrastructure, security controls, implementation methods, or proprietary technologies.

## Supported Materials

Security reports concerning materials publicly released and controlled by xBxBio may be reviewed as appropriate.

Because this repository primarily contains public technical and educational information rather than the complete proprietary xBxBio production platform, not every report concerning hypothetical, conceptual, third-party, or unpublished functionality will necessarily represent an xBxBio security vulnerability.

Security applicability depends upon the affected technology, implementation, deployment, ownership, intended use, and context.

## Healthcare and Patient-Safety Considerations

Security issues affecting healthcare technologies can potentially have consequences involving:

* Confidentiality
* Integrity
* Availability
* Privacy
* Clinical information
* Data provenance
* System reliability
* Healthcare operations
* Clinical workflows
* Patient safety

Reports that reasonably suggest an immediate risk to patient safety or unauthorized exposure of sensitive healthcare information should clearly indicate that concern.

**Do not publicly disclose sensitive information to demonstrate urgency.**

Contact **[ken@xbxbio.com](mailto:ken@xbxbio.com)** directly.

## Coordinated Disclosure

When appropriate, xBxBio may work with a reporter to understand and evaluate a reported security concern.

Depending on the circumstances, evaluation may include:

* Confirming receipt of the report
* Requesting additional non-sensitive information
* Assessing reproducibility
* Evaluating potential impact
* Determining whether the report affects an xBxBio-controlled technology
* Evaluating potential privacy or patient-safety implications
* Identifying appropriate remediation or risk-management actions
* Coordinating responsible disclosure when appropriate

The existence or submission of a security report does not by itself establish that a vulnerability has been confirmed.

The timing and manner of any public disclosure should take into account remediation, privacy, confidentiality, security, patient safety, legal obligations, and other relevant risks.
